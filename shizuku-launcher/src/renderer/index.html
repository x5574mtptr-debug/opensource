激活 Shizuku

未选择设备

工具会自动按顺序尝试多种启动方式，兼容 Android 10/11+ 与 Shizuku v13.6/v13.7+， 无需你手动挑选。首选方案完全绕开文件系统限制，成功率最高。

adb -s <设备> shell sh /sdcard/Android/data/moe.shizuku.privileged.api/start.sh

启动方式说明

1
app_process 直接拉起 首选。用 pm path 定位 Shizuku APK，再以 app_process 直接运行服务进程，完全不碰 Android/data 目录 —— Android 11+ 的分区存储限制和 v13.7 移除 start.sh 的问题都绕开了。
2
start.sh 直接执行 兼容 Android 10 及以下与旧版 Shizuku。此路径在 Android 11+ 会被系统拒绝，属预期现象。
3
starter 复制到 /data/local/tmp Shizuku v13.6 官方推荐方式。需能读取 Android/data，部分机型不可行。

常见问题速查

提示找不到 start.sh 脚本

这在 Android 11+ 上是正常现象 —— 分区存储限制让 adb 无法读取 Android/data，而 Shizuku v13.7 起更是彻底移除了该脚本。工具会自动改用 app_process 直启，无需你处理。

提示 Permission denied

同样是 Android 11+ 分区存储限制，不是权限没开。工具会自动切换方案。若 app_process 直启也失败，再检查 MIUI 的「USB 调试（安全设置）」与 ColorOS 的「权限监控」。

提示未安装 Shizuku 应用

手机上确实没装 Shizuku，或装的是修改版导致包名不对。从官方渠道安装后打开一次即可。

设备显示 unauthorized

手机上的授权弹窗没确认。撤销 USB 调试授权后重新插拔数据线，再勾选「一律允许」。

激活成功但一会儿又失效

手机重启后 ADB 会话结束，Shizuku 服务随之停止，属正常现象，重新激活即可。

激活后如何授权应用

  1. 在手机打开 Shizuku 应用，确认首页状态显示 已启动。
  2. 进入「设置 / 授权管理」，找到需要使用 Shizuku 的应用。
  3. 打开该应用右侧的开关，允许其使用 Shizuku。
  4. 回到目标应用重启，即可使用原本需要 ADB 权限的功能。
